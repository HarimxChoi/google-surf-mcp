# Search extraction consolidation

## Contract

- General entry points are `search`, `search_parallel`, and `extract`.
- `scholar_search` is limited to academic metadata.
- `search_extract` is removed.
- `search` and `search_parallel` accept optional extraction settings.
- Extraction defaults off and failures remain isolated from search results.
- Parallel extraction has one call-wide limit of 10 URLs.
- SearchApi fallback tries the current browser tier once and does not wait for human CAPTCHA recovery.

## Falsifiers

- Default search starts an extraction worker or changes the existing result shape.
- One extraction failure turns a successful search into a tool error.
- Parallel extraction exceeds the call-wide limit or repeatedly fetches one URL.
- The MCP tool list still exposes `search_extract`.
- Tool schemas do not state when to use search, parallel search, extraction, or Scholar.
- Fallback mode calls human CAPTCHA recovery before SearchApi.

## Deferred

- Model-specific tool-choice accuracy across MCP hosts.
- Live Google latency under CAPTCHA or parser degradation.
- Extract body caching across repeated calls.

## Live check 2026-08-25

- SearchApi credentials were removed and `SURF_SEARCH_PROVIDER=browser` was forced.
- The existing profile reached `Google CAPTCHA at after-search` in 16.6 seconds.
- A fresh temporary profile was blocked during bootstrap in 5.0 seconds.
- Browser search and live extraction remain open until the IP block clears or a human completes bootstrap.
