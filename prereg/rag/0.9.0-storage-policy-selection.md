# v0.9.0 storage policy selection preregistration

## Decision rule

Choose the policy with the fewest unique searchable bytes only when all conditions hold:

- Lineage pair coverage is 100%.
- Explicit-reference target coverage is within five percentage points of index-all.
- Structured-field query recall at 5 is within five percentage points of index-all.
- Inventory runtime is below 120 seconds.
- Two unchanged runs produce the same inventory digest.

If no compact policy passes every condition, no policy is selected.

## Query construction

- Explicit-reference queries use the 400 characters before and after an explicit file path after removing the path.
- Structured-field queries use only explicit JSON values under `candidate`, `condition`, `decision`, `hypothesis`, `method`, `name`, or `objective`.
- Query generation, target identity, and success scoring do not use an LLM.
- Exact duplicate targets are equivalent when their content hashes match.

## Falsifiers

- A selected compact policy violates any decision condition.
- Query generation includes generated summaries or manual relevance labels.
- The index-all baseline and compact policy are built from different manifests.
- A duplicate body is counted more than once in unique searchable bytes.
- A rerun changes the selected policy without an inventory digest change.

## Deferred

- Human relevance judgments
- Dense retrieval
- Learned reranking
- Semantic experiment grouping
- Binary checkpoint hashing

## Evidence required

- Policy metrics from one manifest
- Inventory digest from two unchanged runs
- Selected policy or explicit no-selection result
