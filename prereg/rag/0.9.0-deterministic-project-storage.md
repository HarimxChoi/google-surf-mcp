# v0.9.0 deterministic project storage preregistration

## Hypothesis

A deterministic inventory can preserve project lineage with less retrieval noise than LLM-selected summaries while retaining every source as metadata or a content reference.

## Scope

- User-approved repository and artifact roots
- File classification from path, extension, Git state, and structured fields
- Exact content deduplication
- Preregistration and result pairing
- Metadata-only, searchable-text, and binary-reference storage tiers
- Self-supervised retrieval evaluation from explicit cross-references
- Short receipts that report stored categories only

## Candidate policies

1. Index every parseable text file.
2. Index tracked source, project documents, preregistrations, and terminal results.
3. Index terminal evidence and referenced source, then load logs and checkpoints on demand.

No policy may discard file metadata. LLM summaries are derived fields and cannot control inclusion, evidence status, or lineage.

## Metrics

- Exact-reference recall
- Preregistration-to-result recall
- Latest-terminal-result accuracy
- Duplicate searchable bytes
- Searchable bytes and record count
- Inventory and query latency
- Unpaired or ambiguous experiment rate

## Falsifiers

- A tracked or artifact file is absent from the metadata inventory.
- Two projects retrieve each other's local records.
- Exact duplicates are indexed as separate searchable bodies.
- A result is linked to the wrong preregistration.
- An LLM-generated field changes storage tier or evidence status.
- A compact policy loses more than five percentage points of exact-reference recall against index-all.
- Re-running an unchanged inventory changes record identities or active tiers.

## Deferred

- Semantic embeddings
- LLM-generated project summaries
- Code graph extraction
- Binary checkpoint content ingestion
- Automatic deletion
- External PKM sync

## Evidence required

- WarpQuant repository and artifact-root inventory
- Policy comparison on the same immutable inventory manifest
- Re-run stability check
- Focused unit tests
- Full test suite, typechecks, and build
