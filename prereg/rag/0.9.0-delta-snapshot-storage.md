# v0.9.0 delta snapshot storage preregistration

## Hypothesis

One mutable active projection plus immutable snapshot deltas preserves project history without duplicating every project membership on each index run.

## Scope

- One active entry per project and stable path ID
- Content-addressed text bodies
- Immutable added, modified, and removed entry deltas per snapshot
- Active snapshot pointer updated after all writes
- Search restricted to active entries

## Falsifiers

- An unchanged rerun writes a new snapshot or entry delta.
- Changing one file writes more than one modified delta when no other input changed.
- A removed file remains searchable.
- A previous text body disappears from content-addressed storage.
- A failed index replaces the active snapshot pointer.
- Active entry count grows when paths are unchanged.

## Deferred

- Snapshot deletion
- Content-body garbage collection
- Binary delta hashing
- Snapshot reconstruction API
- Cross-project body encryption

## Evidence required

- Initial index test
- Unchanged reuse test
- One-file modification test
- Removed-file test
- Active retrieval test
