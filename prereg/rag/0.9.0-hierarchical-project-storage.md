# v0.9.0 hierarchical project storage preregistration

## Trigger

The flat WarpQuant inventory did not finish within five minutes because it expanded dependency environments, model caches, and upstream source mirrors as project-owned files.

## Hypothesis

A deterministic hierarchical inventory can preserve every collection boundary while expanding project-owned source and evidence quickly enough for interactive use.

## Scope

- File records for project source, documents, configurations, and evidence
- Collection records for dependency environments, caches, generated builds, downloads, and upstream source mirrors
- Path-rule-only boundary decisions
- On-demand expansion of a collection when a user explicitly searches or imports it
- The same policy benchmark as the flat inventory

## Falsifiers

- The WarpQuant inventory exceeds two minutes on the current machine.
- A project-owned preregistration or terminal result is hidden inside a collection record.
- Re-running an unchanged inventory changes IDs or collection boundaries.
- A collection is expanded because of an LLM label rather than a path rule or user request.
- A file outside the approved roots is read.

## Deferred

- Collection byte totals
- Binary content hashes
- Automatic collection expansion
- Semantic classification
- External storage cleanup

## Evidence required

- First flat-run elapsed time and termination
- Hierarchical-run elapsed time
- File and collection counts
- Preregistration-to-result recall by policy
- Re-run identity comparison
