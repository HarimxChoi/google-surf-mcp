# Unified source retrieval

Date: 2026-08-26

## Hypotheses

1. Web pages, papers, and repositories can share `search`, `search_parallel`, and `extract` without changing the Scholar metadata boundary.
2. Independent exact, BM25, vector, graph, and live lanes followed by source-neutral RRF and one reranker preserve exact-code and provenance correctness.
3. One expanded live round and a fresh-web floor expose new evidence without unbounded Google requests.

## Gates

- Browser search runs on every research search call.
- Exact, BM25, vector, and graph lanes run independently in hybrid mode.
- Top 10 includes two fresh unique web results when at least two exist.
- A search uses at most two live rounds.
- `none` or `metadata` reads a GitHub README without cloning.
- `abstract` and `full` return the same repository eligibility decision.
- At most one eligible repository is queued per call.
- Repository indexing does not replace existing project roots.
- Cross-project leakage and invalid provenance remain zero.
- Shared reranking loses at most 0.01 Recall@10 and 0.01 nDCG@10 against candidate RRF.

## Falsifiers

- A local hit suppresses all available fresh web evidence.
- Source type changes rank without evidence from a retrieval lane or reranker.
- A large repository blocks the search call or consumes source storage automatically.
- Abstract and full disagree on repository eligibility.
- Concurrent retrieval publication produces a partial active index or an unhandled write conflict.

## Open

- Human-reviewed mixed-source relevance labels
- Real GitHub API rate-limit and checkout failure evaluation
- Shared reranker quality and latency on the full WarpQuant corpus

## Deferred

- Private repository authentication beyond an optional GitHub token
- Cross-encoder or late-interaction rerankers
- Automatic indexing of repositories above the configured source limits
